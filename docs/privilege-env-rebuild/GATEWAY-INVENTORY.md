# Gateway inventory and naming (decided 2026-11-23)

Scheme: **`mcpgw-<where>-<role><n>`**. Names never contain a PingOne environment name, because the environment behind a gateway changes (`pingid` became `Pingid-privilege` within a week).

- **where**: `cm` = namespace `ping-devops-cmuir`, `ct` = namespace `ping-devops-curtismuir`, `local` = the owner's Mac.
- **role**: `lb` front door, `pool` behind the load balancer and takes traffic, `spare` running but parked, `dev` development or demo gateway outside the pool, `retired` old-tenant gateway scaled to 0.
- Cluster ID in the console for every node of the new tenant: **`ai-demo-cmuir`** (it is the mesh cluster of all 31 apps; it cannot change after registration). Individual nodes are told apart by the names below, not by cluster ID.

Kubernetes labels `ping.demo/gateway`, `ping.demo/where`, `ping.demo/role` and annotation `ping.demo/purpose` are set on each Deployment. List them:
`kubectl get deploy -A -l ping.demo/gateway -o custom-columns='NS:.metadata.namespace,DEPLOY:.metadata.name,NAME:.metadata.labels.ping\.demo/gateway,ROLE:.metadata.labels.ping\.demo/role'`

## Upgrading the gateway image (staged roll, done 2026-11-27 on pool2, pool1, new1 and 2026-11-28 on spare1, nyl: v1.261120 → v1.261127)
Newest tag on `public.ecr.aws/s7q1z8z4/privilege-aigw` was v1.261127; `latest` matched none of the v1.2611xx tags, so **pin the version, never `latest`**. One node at a time, in this order (least traffic first), checking before the next:
1. Backup (mode 600) to `~/.config/demo-kit/backups/gw-<node>-upgrade-<ts>/`: `helm get values -a`, `helm get manifest`, the Deployment yaml (new1 also the `mcpgw-lb-config` ConfigMap). Rollback copies of this roll: `gw-pool2-upgrade-20261127-182332`, `gw-pool1-upgrade-20261127-182830`, `gw-new1-upgrade-20261127-183223`.
2. Values file holding **only** `image.tag` changed from the deployed values. Pin the live `proxyToken` and `replicaCount` when they were set by hand. Never `helm rollback` blindly.
3. `helm upgrade --dry-run=server`, then render and diff against the deployed manifest: it must be one image line.
4. Apply, `kubectl rollout status` (Deployments use strategy Recreate; the PVC `/procyon/ssl` keeps the node identity, so there is no re-enrolment).
5. Test the node's own host directly, before it takes traffic (9 checks per node on 2026-11-27, all passed): health, a keyed call on a door, tool list, a bad key refused with 401, and the like.
6. Promote in HAProxy at once, or the restarted backend stays out for about 10 minutes: `echo "set server gateways/<backend> health up" | nc 127.0.0.1 9999` in each `mcpgw-lb` pod.
Helm revisions made: pool2 → 6, pool1 → 15, new1 (release `agentless-mcpgw`) → 111. New in this image: a `ShadowAIPolicyService ... Unimplemented` log line at start; cosmetic, no effect on traffic. **Not yet re-tested on v1.261127:** a held (human-in-the-loop) call end to end, because it sends a phone push. spare1 (rev 5) and nyl (rev 40) followed on 2026-11-28 with the same recipe; backups `gw-spare1-upgrade-20261128-034156` and `gw-nyl-upgrade-20261128-034156`. spare1 stays in HAProxy maintenance. **Drift risk:** AI-DEMO2 `pingone-privgateway-helm-main/agentless/gateway1-lb.values.yaml` still pins `image.tag: v1.261120` (and `docker-compose.yml` an older digest); a `helm upgrade` of release `agentless-mcpgw` from that overlay would downgrade new1. Update the overlay in an AI-DEMO2 PR before the next upgrade from it.

### nyl restart trap (2026-11-28): the upgrade took NYL down for about 10 minutes
`agentless-mcpgw` in `ping-devops-cmuir` (release `agentless-mcpgw2`) has 10 containers, all `imagePullPolicy: Always`, strategy Recreate. A restart re-checks the registry for every sidecar. Four of them, `ghcr.io/curtismu7/ai-demo2-mcp-{grafana,banking-rest,pingone,promptguard}:sha-1c7152bb…`, answered **403 Forbidden** (`mcp-brave` pulled fine); `mcp-openapi-banking` then crash-looped only because it reads its spec from `localhost:8082`, served by banking-rest. The pod stayed 5/10 and the host returned 503.
- **Cause found:** the four packages are **private with no linked repository**; `mcp-brave` is public and linked to `curtismu7/AI-DEMO2`. The pull secret `ghcr-pull-secret` (user `curtismu7`) cannot read unlinked private packages. Why it could before is not known (the previous pod, 4 days old, pulled them).
- **Live recovery:** `kubectl patch` of those four sidecars to `imagePullPolicy: IfNotPresent`, so the node reuses its cached copies. **It is not in Helm: the next `helm upgrade agentless-mcpgw2` reverts it and the pod fails again,** and a restart onto a different node has no cache.
- **What the two pull secrets can read** (status codes only, tested 2026-11-28): `ghcr-pull-secret` (user `curtismu7`, classic token) reads the `ghcr.io/cmuir_pingcorp/ai-demo-mcp-*` copies (200) but gets 403 on the `curtismu7/ai-demo2-mcp-*` ones; `ghcr-pull-curtismu7` (also user `curtismu7`, a different token) reads the `curtismu7` ones (200) but not the `cmuir_pingcorp` ones (404). nyl's pod uses `ghcr-pull-secret` only, which is why four sidecars fail. No new token is needed.
- **Permanent fix (owner go needed, not done):** either (a) point nyl's four sidecar images at the `cmuir_pingcorp/ai-demo-mcp-*` copies, as `mcpgw-ct-new1` and pool1 already run them (grafana and promptguard copies exist there; confirm the sha matches first), or (b) add `ghcr-pull-curtismu7` next to `ghcr-pull-secret` in nyl's `imagePullSecrets`. Either way nyl restarts once (about 1 to 2 minutes down). Then put `imagePullPolicy` back to `Always` through Helm and drop the live patch.
- **Before any restart or upgrade of this release,** fix the access first, or re-apply the patch straight after.

## Sign-in client (fixed 2026-11-28: every node on `1bd04cae`)
Every gateway's browser sign-in uses the PingOne app **`1bd04cae` "PingOne Privilege"** (the Privilege tenant's own OIDC app), which holds a callback for each active node host (`mcpgw.ai-demo…`, `mcpgw-pingid.ai-demo…`, `mcpgw-pingid3.ai-demo…`, `mcpgw-pingid2.ai-demo…`) and the console's own callback. On 2026-11-27 a read of each release showed new1 (`agentless-mcpgw`, ct) still on `d8fbd995` `mcpgw-oidc`; on 2026-11-28 it was moved to `1bd04cae` (Helm revision 112): same client id and secret as pool1, and the scopes aligned to pool1's `openid profile email` (new1 had asked for `offline_access p1:read:env p1:read:user p1:read:application`, which `1bd04cae` was not checked for). Only the three OIDC lines of the Secret changed (dry-run diff), the pod was recreated, and `mcpgw-ct-new1` was promoted in both `mcpgw-lb` pods. Rollback copy (mode 600): `~/.config/demo-kit/backups/gw-new1-signin-20261128-042813`.
- **Check used** (no browser, no password): read the three values new1 now holds, send PingOne the authorize request with the shared-host `/callback` and those scopes (answer: 302 to the PingOne sign-on page, no error), and call the token endpoint with the client secret and a bogus code (answer: `invalid_grant`, not `invalid_client`). A full browser sign-in through new1 was not run.
- `1bd04cae` has no token-exchange grant; `d8fbd995` has. Nothing on the gateway sign-in needed it (pool1 and pool2 have always used `1bd04cae` on the same host).
- `d8fbd995` `mcpgw-oidc` is now unused (shared-host callback only). Delete it only after a sweep confirms no lab or PGC references it.
- **Before re-enrolling `mcpgw-cm-spare1` (it still carries the old-tenant app `33bb98ce` in its OIDC Secret):** `1bd04cae` already has `https://mcpgw-pingid2.ai-demo…/callback`; point spare1's `agentless-mcpgw-pingid2-oidc-config` Secret at `1bd04cae` with the new tenant's URLs.
- Lesson: never print a parsed Helm values block. `proxyToken` (the node's enrolment token) sits in the same values, and a comparison that prints every differing key prints it whole. Mask by key name, not by guessing which keys are secret.

## Original rename plan (needs a chart change)
The HAProxy backend names (`gateway-pingid-1/2/3`, `gateway-old-1`) were generated by the chart `pingone-privgateway-helm-main/agentless/agentless-mcpgw/templates/loadbalancer-haproxy.yaml` from `loadBalancer.peers[].name`. The OAuth callback strips the node tag from `state` with a regex hard-coded in the template: `regsub(~gateway-[0-9]+,,g)`. **Renaming the backends without changing that regex breaks logins through `mcpgw.ai-demo…`.** The change is: make the regex generic (for example `~[A-Za-z0-9_-]+` after the `~`), rename the peers in `gateway1-lb.values.yaml`, render with `helm template`, diff against the live ConfigMap, then apply. It is an AI-DEMO2 repo change, so it goes through a worktree, a PR and a review. Do not hand-edit the live ConfigMap names.

Target backend names: `gateway-pingid-1` → `mcpgw-cm-pool1`, `gateway-pingid-3` → `mcpgw-ct-pool2`, `gateway-pingid-2` → `mcpgw-cm-spare1`, `gateway-old-1` → `mcpgw-ct-retired1`.

Hostnames: add the new names next to the old ones (`mcpgw-cm-pool1.ai-demo…`, and so on) as extra ingress hosts and certificate names, then move labs over, then retire the old hosts. Helm release names stay as they are unless a gateway is reinstalled anyway.
