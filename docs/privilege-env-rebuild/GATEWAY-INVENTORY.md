# Gateway inventory and naming (decided 2026-11-23)

Scheme: **`mcpgw-<where>-<role><n>`**. Names never contain a PingOne environment name, because the environment behind a gateway changes (`pingid` became `Pingid-privilege` within a week).

- **where**: `cm` = namespace `ping-devops-cmuir`, `ct` = namespace `ping-devops-curtismuir`, `local` = the owner's Mac.
- **role**: `lb` front door, `pool` behind the load balancer and takes traffic, `spare` running but parked, `dev` development or demo gateway outside the pool, `retired` old-tenant gateway scaled to 0.
- Cluster ID in the console for every node of the new tenant: **`ai-demo-cmuir`** (it is the mesh cluster of all 31 apps; it cannot change after registration). Individual nodes are told apart by the names below, not by cluster ID.

Kubernetes labels `ping.demo/gateway`, `ping.demo/where`, `ping.demo/role` and annotation `ping.demo/purpose` are set on each Deployment. List them:
`kubectl get deploy -A -l ping.demo/gateway -o custom-columns='NS:.metadata.namespace,DEPLOY:.metadata.name,NAME:.metadata.labels.ping\.demo/gateway,ROLE:.metadata.labels.ping\.demo/role'`

## Sign-in client (decided 2026-11-25)
Every gateway's browser sign-in uses the PingOne app **`1bd04cae` "PingOne Privilege"** (the Privilege tenant's own OIDC app). Both pool nodes already run it (read back from `agentless-mcpgw-pingid-oidc-config` in both namespaces), and the app holds a callback for every active node host: `mcpgw.ai-demo…`, `mcpgw-pingid.ai-demo…` (pool1), `mcpgw-pingid3.ai-demo…` (pool2). The alternative app `d8fbd995` `mcpgw-oidc` (shared-host callback only, nothing points at it) stays enabled but unused; delete only after a sweep confirms no lab or PGC references it. **Before re-enrolling `mcpgw-cm-spare1` (it still carries the old-tenant app `33bb98ce` in its OIDC Secret): add `https://mcpgw-pingid2.ai-demo…/callback` to `1bd04cae`, then point spare1's `agentless-mcpgw-pingid2-oidc-config` Secret at `1bd04cae` with the new tenant's URLs.**

## Still to rename (needs a chart change, queued)
The HAProxy backend names (`gateway-pingid-1/2/3`, `gateway-old-1`) are generated by the chart `pingone-privgateway-helm-main/agentless/agentless-mcpgw/templates/loadbalancer-haproxy.yaml` from `loadBalancer.peers[].name`. The OAuth callback strips the node tag from `state` with a regex hard-coded in the template: `regsub(~gateway-[0-9]+,,g)`. **Renaming the backends without changing that regex breaks logins through `mcpgw.ai-demo…`.** The change is: make the regex generic (for example `~[A-Za-z0-9_-]+` after the `~`), rename the peers in `gateway1-lb.values.yaml`, render with `helm template`, diff against the live ConfigMap, then apply. It is an AI-DEMO2 repo change, so it goes through a worktree, a PR and a review. Do not hand-edit the live ConfigMap names.

Target backend names: `gateway-pingid-1` → `mcpgw-cm-pool1`, `gateway-pingid-3` → `mcpgw-ct-pool2`, `gateway-pingid-2` → `mcpgw-cm-spare1`, `gateway-old-1` → `mcpgw-ct-retired1`.

Hostnames: add the new names next to the old ones (`mcpgw-cm-pool1.ai-demo…`, and so on) as extra ingress hosts and certificate names, then move labs over, then retire the old hosts. Helm release names stay as they are unless a gateway is reinstalled anyway.

**Not migrated:** PingID (no PingID service, no `Multi_Factor` policy in the new environment). See the guide, section "NOT MIGRATED: PingID".
